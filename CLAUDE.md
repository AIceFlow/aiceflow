# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

AIceFlow website. Since October 2026 the home page is built around the **AIceFlow Governance Gateway**
(primary product, with AIceFlow Trace) and **Agents von AIceFlow** (service), aimed at managing
directors in the German Mittelstand. German only, Sie-Form. The design source is the prototype in
`../governance-layer` (scroll story, canvas „Governance Gateway – Redesign“).

## Commands

```bash
npm run dev        # Start dev server (port 8080)
npm run build      # Production build
npm run lint       # ESLint
npm run preview    # Preview production build
```

## Tech Stack

- React 18 + TypeScript (Vite, SWC)
- Tailwind CSS 4 via `@tailwindcss/vite`, configured in `src/index.css` (`@theme`, no `tailwind.config.ts`),
  with HSL design tokens defined there
- AIceFlow Design System in `design-system/` (tokens, fonts, component classes; rules below), imported in
  `src/index.css`
- shadcn/ui + Radix UI primitives (48 components in `src/components/ui/`)
- Framer Motion for animations
- Supabase for form submissions
- Google Ads + LinkedIn Insight Tag for analytics

## Architecture

**App shell** (`src/App.tsx`): Wraps the app in QueryClientProvider → LanguageProvider → TooltipProvider → BrowserRouter. CookieBanner sits outside the router.

**Home page** (`src/pages/Index.tsx`): `<Landing />` + `<SiteFooter />` from `src/components/landing/`.
`Landing` injects `src/landing/markup.html` (raw HTML: SVG stage, nine-chapter scroll story (chapter 08 „ChatGPT, Claude und n8n“: two chat windows since 2026-11-11 and an n8n window since 2026-11-21, whose requests run through the Gateway, the chats into the ERP, the n8n flow into the DMS; OpenAI, Claude and n8n marks from simple-icons, used at the user's request; the film shows only the two chats), Angebot,
Trace, Einsatz, Anbindung, Betrieb, Pilot, Team, Termin, film dialog) and calls `initLanding()` from
`src/landing/initLanding.js`, which wires the vanilla modules (`stage.js`, `story.js`, `approval.js`,
`drill.js`, `trace.js`, `connectors.js`, `film.js`, `booking.js`; GSAP ScrollTrigger + Lenis) and returns a teardown
that is run when the route changes. Styles: `src/landing/landing.css` (plain CSS; colors and fonts from
the design-system tokens since 2026-11-15, see Styling). Change the page in `../governance-layer` first, then copy markup,
modules and CSS over (paths for `logo/`, `film/`, `team/` are absolute here). The former sections
(Hero, About, Services …) are still in `src/components` but no longer rendered.

**Routing**: React Router v6 with `basename` from `import.meta.env.BASE_URL`. Routes: `/` (Index),
`/impressum`, `/datenschutz` (both via `LegalLayout`), `*` (NotFound). GitHub Pages serves deep links
through `public/404.html` → `index.html` redirect. The footer links Impressum and Datenschutz, and
„Cookie-Einstellungen“ resets the consent so the banner shows again. The cookie banner links the
Datenschutz page.

**Booking**: Google Calendar appointment schedule, embedded only after a click (`src/landing/booking.js`).
Opening it fires the gtag event `termin_kalender_geoeffnet` (`src/utils/analytics.ts`). The film is
served from the Supabase bucket `public-assets/marketing` (render of 2026-11-11, 99.3 s; `FILM_T` in `film.js` holds the scene starts).

**Anbindung** (since 2026-11-21, between Einsatz and Betrieb): `src/landing/connectors.js` puts the logos
of connectable systems on three spiral arms that flow into the Gateway tile (the „Strudel“). The list of
six groups highlights the matching logos, like the list in Trace; hovering a tile shows the system's name.
The logos are one self-hosted sprite, `public/connectors/sprite.webp`, loaded when the section gets near;
`src/landing/connectors-data.js` lists them in sprite order. Both files are generated by
`scripts/build-connectors.mjs` (needs `sharp`, which is not a dependency: `npm i --no-save sharp`) from the
public catalogue of the connector library we use (`CATALOG` in that script), the selection is `PICK` there.
Only systems that exist in the catalogue are shown (no DATEV, no SAP ERP, no lexoffice). The page never names
that library (user decision); „über 700“ in the copy is the size of the catalogue (745 system connectors on
2026-11-20). The logos keep their brand
colors, at the user's request. This section exists only here, not in `../governance-layer`.

**Agent figure** (since 2026-11-21): an agent is a light tile with a dark display, a line sign for its task
(invoice, rising chart, cart; code brackets for the customer's own agent) and a small spark that says „KI“
(blue, white for the own agent). It replaced the robot heads with eyes and antenna, which the user found
unprofessional; so that readers still see these are AI agents, the row on the stage is labelled „KI-AGENTS“.
The agents keep their names („Rechnungs-Agent“), without a „KI-“ prefix. On the
stage the sign and the spark fade in via `{{agN.sign}}` / `{{agN.led}}` (`stage-markup.js`, `stage.js`); the
Angebot pictures and the Einsatz list use the symbols `agent-rechnung`, `agent-einkauf`, `agent-vertrieb`,
`agent-own` at the top of `markup.html`. The film and its thumbnails still show the robots.

**Scroll pace of the story** (since 2026-11-21): `story.js` maps the scroll position to the story position
`p` through the table `PACE` (how much scroll way each stretch of `p` gets), not linearly. Dense stretches
(the four layers, the drill-down levels, the three windows) get more way, idle ones less, and at each
chapter's settled state (`TARGET` in `stage.js`) the story holds for a while. The stage timings are
unchanged: to change the pace, edit `PACE`, not the `seg(p, …)` values in `stage.js`. The total length is
`--chapter-vh` in `landing.css` (156 desktop, 140 compact) and should stay near (sum of `PACE` + 100) / 9.
The story follows the scroll at no more than `FOLLOW` way units per second, so a fast swipe plays out
instead of skipping; while the stage is off screen it follows at once. Jumps (`scrollToP`) land in the
middle of a hold. Chapter 05 (approval, booking, oversight) runs on time, not on scroll, so on the first
pass the story waits at that chapter's hold until it has played once (`approval.hold`, at most about
5 s): scrolling on is held there, scrolling back is always free, and jumps (progress bar, navigation,
anchors, End key) pass through. A click on „Freigeben“ shortens the wait.

## Key Conventions

**Text content**: the home page copy lives in `src/landing/markup.html`, legal texts in
`src/pages/Impressum.tsx` and `src/pages/Datenschutz.tsx`. Every visible „AIceFlow“ uses `span.aice`
(`BrandMark` in React); its „AI“ is in the CI blue of the logo (`.aice__ai`, `--blue`). The user decided
this on 2026-11-21, against the design-system export, whose README and Glossar still say „im Text
einfarbig“. Every product mention in running text uses `span.prod` and shows as a product mark: the
signet (`/logo/aiceflow-mark.svg`, drawn by `.prod::before`) followed by the name in Martian Mono caps,
e.g. „✕ TRACE“, „✕ GATEWAY“. The signet stands for „AIceFlow“ (the user's idea, 2026-11-21). A full name
is `span.prod.prod--full` with `span.aice` and `span.prod__name`: the wordmark stays in the markup for
screen readers and copying, but is visually hidden behind the signet. Headings (h1 to h3), eyebrows,
panel lines and pills write the name out in their own font, without the signet. A new product mention
must get `span.prod`, otherwise it looks unmarked. The translation object in
`src/hooks/useLanguage.tsx` (en/de) only serves the former components.

**Path alias**: `@/` maps to `src/` (configured in both `vite.config.ts` and `tsconfig.app.json`).

**Styling**: the home and legal pages use `src/landing/landing.css` (plain CSS, deliberately not Tailwind;
its tokens avoid shadcn names, e.g. `--ring-hair`). Since 2026-11-15 it uses only design-system colors
and fonts: its own names (`--bg`, `--ink-2`, `--amber` …) point to the tokens, `--ink`, `--surface`,
`--blue` and `--font-sans` come straight from `design-system/tokens.css`. Big headings in Gloock
(`--font-display`), text in Host Grotesk, markers, timestamps and amounts in Martian Mono. The stage SVG
(`stage-markup.js`, inline SVG in `markup.html`) uses `var(--token)` / `color-mix()` in style
attributes, `stage.js` reads the tokens it mixes at runtime. Old colors map: navy → ink, blue-grey →
the grey ramp, amber → signal, orange → stop, turquoise (own agent) → ink; the ChatGPT and Claude marks
keep their colors. Nunito remains only for the „AIceFlow“ lettering next to the signet on the gateway
(logo lockup). Everything
else uses Tailwind utility classes with the HSL variables from `src/index.css`. `src/index.css` imports
`landing.css` into Tailwind's `base` layer (not from JS): unlayered, its reset would beat every Tailwind
utility. Tailwind only scans `src/**/*.{ts,tsx}` (`source(none)` + `@source`), not `markup.html`.

**Design system in the build**: `src/index.css` imports `design-system/tokens.css` and `components.css`
into the `base` layer before `landing.css`, and `design-system/tailwind.css` for the classes (`bg-paper`,
`font-display` …). `body` background and text color come from `landing.css` (paper, ink), not from the
shadcn variables. `--border` and `border-border` belong to
the design system; the shadcn border is `--shadcn-border` / `border-shadcn-border`. Do not edit files
in `design-system/`; a new export replaces the folder. Logos are in `public/logo/` (the design-system
previews expect `/logos/`).

**Icons**: Use `lucide-react`.

**Adding shadcn/ui components**: Configured via `components.json` (style: default, baseColor: slate, cssVariables: true).

## AIceFlow Design System

> **Decision of 2026-11-15:** from the design system only the fonts and colors are binding. They were
> applied to the existing page in place: same content, same structure, same animation. Its page layouts
> and component templates (af-hero „Einstieg“, Schichtbild preview, Spalten, Band …) are not used. Two
> attempts built from them were rejected; they are in git stashes. The rules below apply where they
> concern type, color and wording.

Diese Regeln gelten für jede Änderung an Oberfläche, Texten und Bildern dieser Website. Die Quelle der Wahrheit ist der Ordner `design-system/`.

### Vor jeder Änderung lesen

1. `design-system/README.md`: Farbe, Schrift, Layout, Logo.
2. `design-system/01-Marke.md`: Positionierung, Botschaften, Ton.
3. `design-system/03-Glossar.md`: welche Wörter wir verwenden und welche nicht.
4. Für Website-Abschnitte das passende Vorbild unter `design-system/components/<Name>/` (README.md und preview.html): Einstieg, Spalten, Band, TraceZeile, Status, Schichtbild, Button, Abschnittsmarke.

### Technik

- Farben, Schriften, Abstände und Radien nur über die Tokens aus `design-system/tokens.css` (CSS-Variablen wie `var(--ink)`, `var(--font-display)`) oder die Tailwind-Klassen aus `design-system/tailwind.css` (`bg-paper`, `text-ink`, `font-display`). Keine Hex-Werte im Code.
- `design-system/components.css` enthält die fertigen Klassen (`af-hero`, `af-trace`, `af-btn` …). Nutze sie oder baue Komponenten exakt nach ihrem Vorbild.
- Schriften liegen in `design-system/fonts/` und werden selbst gehostet. Nie Google Fonts einbinden.
- Dunkles Thema über `data-theme="dark"` am `<html>`.
- Tokens nie direkt in `tokens.css` ändern. Änderungen am Design System passieren im Design System und werden neu exportiert.

### Harte Regeln

- Blau (`--blue`) nur als Akzent: Abschnittsmarke, Haken in „Freigegeben“, Prüfkante, Kennziffern, Signet. Nie als Fläche, Button oder Hinterlegung. Links in `--blue-strong`.
- Gloock (`font-display`) nur ab 32px, höchstens zwei Zeilen, im Einstieg drei. Nie für Fließtext.
- Website-Text in Host Grotesk, Lesetexte (Blog, Whitepaper) in Newsreader, Daten und Marken in Martian Mono.
- Jede Seite: Einstieg in `--ink` mit Protokoll, danach hell auf `--paper`, am Ende ein Band in `--well` mit genau einem Button.
- Keine Schatten, keine Verläufe, kein Glas, keine Pillen, keine Icons außer den vier Status-Formen, keine Stockfotos, keine KI-Bilder.
- Texte: kurze Aussagesätze, Sie-Form, keine Gedankenstriche, keine Ausrufezeichen, keine Füllwörter wie „nahtlos“ oder „KI-gestützt“, keine Fachkürzel wie MCP oder LLM.
- Keine erfundenen Kundennamen, Zitate oder Zahlen.

### Vor dem Abschluss prüfen

- Kein Hex-Wert und keine fremde Schrift im Diff.
- Blau nirgends als Fläche.
- Kontrast Text mindestens 4,5:1 in hellem und dunklem Thema.
- Auf 390px Breite geprüft (Telefon).
- Alle neuen Texte gegen das Glossar gelesen.
